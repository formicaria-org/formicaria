# Features — the index (always-read)

One line per feature: **what it is · status · where the detail lives.** This is the discovery layer —
it names what exists and points at the on-demand doc, so nothing durable is invisible. Keep it
**brief**: a feature earns a dedicated `features/<slug>/` doc only when its lessons overflow a line
here. Status: ✅ shipped · 🟚 partial · 📋 planned. "the code wins" — verify a claim before trusting it.

| **Notes & storage** | ✅ | files-as-truth: one note = one `<ulid>.md`; `Store`/`FileStore`/`MultiStore`, FTS5 index (disposable) | `overview.md` (seams) · `decisions.md#seams` |
| **Query & views** | ✅ | pure `fm-query` engine; board/agenda/timeline/search, generic literal-free renderers — **the feed is a place you read and discuss since 2026-08-31**: a post carries a char-capped
`excerpt` (several lines, markdown stripped, filled only by `recent()`) faded out with a mask, is an
`<article>` whose title+picture is the one button that opens the note, and carries a reply count
from a single `thread_roots` call — tap it and one discussion expands with the last three messages
and a box, flat and reply-only. Editing stays in the pane (one editor per note), bodies are never
Markdown-rendered in a list, and there is no double-tap; **the timeline has two densities since
2026-08-30**: a *feed* (default) showing each note as a post with its picture, its first line, its vault and its last editor, which is what makes a shared vault legible as one stream; and the original one-line *list*, switched per pane like the agenda's month/week/list. The feed mounts 30 posts with a button for the rest, because `recent` is unbounded and nothing here is virtualised, `.view` files — **a filtered view names what it leaves out and offers the unfiltered one; the board carries a column rail** (2026-08-24); **saveable from the app** — an arrangement you keep, not a query you write (2026-08-28), **deletable and renameable, recorded in git** (2026-08-30). **The whole authoring surface was withdrawn on 2026-08-31** — no save, rename, delete or board group-by anywhere in the UI, because it was reachable before anyone could learn what a view is; the commands and their tests stay, and a `.view` file written by hand or arriving over git still lists and opens, so the promised design plan is cheap to land. **The board's column rail went with it**, against advice: a filtered view still says what it leaves out, but a board that scrolls no longer says so | `overview.md` · `decisions.md#ui` |
| **Appearance / themes** | ✅ | `<vault>/themes/*.css` — **git-tracked, so a theme travels with the notes; which one is on stays per-device** (like dark/light). Two ways in over one file: a three-question form (accent, text size, font) and a CSS box with live preview. A file richer than the form is shown read-only and **refused, never flattened**. The escape hatch is an **armed-boot guard** (JS, not CSS): a theme nobody could interact with is not put back. `SUPPORTED` in `appearance.ts` is the promised surface — CI fails if the form names a token itself | `decisions.md#ui` (*a theme is a file in the vault*) |
| **Editor & workspace** | ✅ | pane-grid workspace, `/` slash menu at caret, note↔note refs, double-click-to-edit. **Chrome is one element in two placements (2026-08-30)**: a collapsible panel down the left where there is width, the same controls as a bottom bar where there is not — reverses the 2026-08-28 rail removal, because this one *replaces* the top bar instead of joining it. **One view at a time is the default since 2026-08-31, and `auto` is gone**: opening a view *re-points* a window that already shows it rather than stacking another (`focusOrOpen`), the open-windows strip is desktop-only, and the arrangement is a set of inherited custom properties so a narrow rule can no longer be half-written — `tiled` stays, opt-in. **The chrome is one row at the top since 2026-08-31**: the pane header is gone in `single` (it belongs to `tiled`, where names, drag handles and per-pane controls earn their row) and `ViewControls.svelte` renders the active view's own controls — grouping, density, a search pane's query box, a saved view's rename/delete — at the end of the bar that names it. Save view moved to the action list; the contributor filter was removed outright; the vault filter is a `menuitemcheckbox` menu that states how much it hides. **Every dialog is bounded by the visible viewport since 2026-09-01** — capped in `dvh` inside the window insets, one scroll surface on the panel, after Back up shipped with no cap and no `overflow` at all (its own primary button fell off the bottom) and Help shipped with no overlay CSS at all, because Svelte scopes `.sheet` to the component that declares it | `decisions.md#ui` (*the chrome moves to a collapsible side panel*; *an overlay is bounded by the visible viewport*) |

| **Mobile / Android** | 🟚 | one shared Rust core on the phone, git-coordinated via libgit2 (`native-git`); jniLibs + foreground service; startup is a contract (`pixi run android-smoke`). **Responsiveness fixed 2026-08-20** — IPC commands are `(async)` (a blocking one parks the JS thread), no per-autosave full-corpus scans, incremental cold start, 16 MB ingest ceiling; **the suite now runs the phone's own branches** (`asPhone()` in `ui/src/lib/harness.ts`). **The shell reads its own window insets since 2026-08-31** — `MainActivity` forwards `WindowInsetsCompat` into the page as the `--safe-*` tokens, closing the guessed floors that put the top bar under the camera cutout and the bottom chips under the navigation bar; `app.css` keeps a floor as the pre-bridge fallback | `mobile-design.md` · `decisions.md#track-m` · `known-issues.md` (what is still open) |
| **Backup & acquisition** | ✅ | two-tier: git push (notes, plus attachments under the vault's `git_assets_max`, itself bounded by a **100MB ceiling** since 2026-09-02 — there is no git-lfs, so the app refuses to write a limit above it and clamps one it did not write) + restic (an opt-in snapshot of the notes dir **and** `blobs/` — never the vault root, so `views/`/`themes/`/history are git's alone); clone/restore via `acquire::naturalise`. **Works on Windows without installing git** since 2026-08-28 — libgit2 is linked where the OS ships no binary, and `vcs` still prefers a real one where there is. **Set up entirely in the app since 2026-08-29**: an access token for an HTTPS remote, a restic repo per vault, and one restic password per machine (`0600`, never in `vaults.json`) — and a *first* backup now records the notes instead of reporting success over an empty repo. **Every surface states its own tier's scope since 2026-09-02**, and the restic writers (`set_restic_repo`/`set_restic_password`/`clear_restic_password`) are refused to paired devices like `/api/backup` already was | `decisions.md#git` (Backup, the Windows widening, the first-backup ordering) · `decisions.md#vault` (the restic password; what each tier carries, and why git-lfs is not taken) |
