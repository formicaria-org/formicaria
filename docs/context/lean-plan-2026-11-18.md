# Leaner formicaria — plan and progress (2026-11-18)

The owner, 2026-11-18: *"brainstorm ways to lean the fm"*, then *"plan and execute"*. Standing rules it
serves: the computer-wide cap (*"keep bounded the memory and cpu usage … top 80 %"*), the APK under
100 MB, *simple server, rich front*, *delete machinery*. Every step is **measured before and after**
the same way, and each that changes a default or what ships gets its `decisions.md` entry.

## Where the weight is (measured 2026-11-18)

| Where | Heaviest |
|---|---|
| Phone APK, 69.5 MB | the core 26.8 MB · Python + yt-dlp 14.1 MB · the assistant (llama, ONNX Runtime, whisper) ~18 MB · rest ~10 MB |
| Browser, a warm start | **+23 % memory** over unmodified Firefox (the first-start figure, +8 %, hid it: Firefox's own first-run work masked the extensions); a feature tab ~12 MB |
| Code | 410 crates (computer), 691 (phone) · 89 k lines of Rust · 68 k lines of UI (`App.svelte` 5.3 k) + 24 k of UI tests |
| UI bundle | 13 MB: Mermaid, Excalidraw + React, the barcode reader (wasm), KaTeX; all loaded on demand |

## Findings along the way

- **Development builds kept full debug information for every dependency**, and the disk filled three
  times in a day. `[profile.dev]` now keeps line tables for our own code and none for dependencies
  (both workspaces): `target/` after `pixi run ci` **12 GB, from 19 GB**; backtraces keep their
  files and lines.

- **The sidebar's button came back at every start** (seen by the warm `browser-check`): Firefox re-adds
  it whenever `sidebar.revamp` turns on, which the kit did at every start. Now on only for side tabs.
- **L2, dependencies**: formicaria's own crates need 70–80 each, and duplicates are few and
  transitive. **The assistant's runtime brings 279 of the server's 305 crates, and 199 of those are
  its photo OCR** (`oar-ocr`, Myrme's `fm-agent-run` feature `ocr`, on by default), plus ONNX Runtime
  in the APK (7 MB). Off, labels are read by the vision model instead (slower). The owner's call,
  with L7. The two web clients are one (`ureq` 2).

## L4 — one interface: the map and the stages (2026-11-18)

**Today.** Two Vite entries: `index.html` → `main.ts` → `App.svelte` (the phone; Tauri serves its
default document) and `feature.html` → `feature/main.ts` → `Feature.svelte` (the computer; `fm-serve`
sends `/f/*` there, `crates/fm-serve/src/main.rs` ~1807). Shared already: `Pane` (every renderer, the
editor), feeds, `NewTab`, `route.ts`, `SaveMedia`, `PrivacySheet`, `SettingsPanel`, `UpdateBanner`.

**What keeps a phone's notes safe lives only in `App.svelte`**: auto-backup, `checkRemotes` and
conflict resolution, the heartbeat with its commit flush, the boot watchdog and pairing/welcome
gates. `listenChanges` is a no-op on the phone (`ipc.ts`), so a feature page there would never
refresh. A careless move would turn these off **without an error**: the stages below move them
first, and each stage is a release.

**Written twice today** (to fold into one each, stage A): the theme bootstrap (`main.ts`,
`feature/main.ts`) and its toggle; the commit debounce with its pagehide flush; a card's move; the
update watch; the window title; `noteShown`; group → views tabs; *new note*; the Save media sheet.

| Stage | What | Risk it removes |
|---|---|---|
| A | **Fold what is written twice** into shared modules; `feature/main.ts` gets `main.ts`'s *cannot start* screen | two fixes for one bug |
| B | **The phone's services as modules** both entries mount: boot gate (watchdog, pairing, welcome), heartbeat + commit flush + auto-backup + remote checks, share intake, theme/appearance | (b) silent loss of backup and sync; (c) boot hangs |
| C | **A change signal on the phone** (from the heartbeat's generations, or a native event) so `listenChanges` works there | feature pages never refreshing |
| D | **An in-document tab host on the phone**: the roller holds feature routes as items (no full-page navigation: the shell's page overlays, the player and share listeners and the timers live in one document) | (a) native overlays and timers lost on navigation |
| E | **Move the phone-only parts into the host** (page items, share and bring sheets, the player, Back/`LAYERS`), migrate `fm-workspace` to the new tab list, re-home the ~40 `App.*.test.ts`, then retire `App.svelte`'s panes | the second interface |

Stage A, done so far: both entries start through `lib/start.ts` (the theme's first paint, and the
*could not start* screen, which the computer's pages lacked); one theme toggle (the phone's copy did
not guard its write). Next in A: the commit debounce with its flush, *new note*, the window title. B to E each need the phone checks (`phone-media-check`, the emulator) green
before release.
