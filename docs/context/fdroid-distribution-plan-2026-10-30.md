# F-Droid and similar: updates without tapping — plan (2026-10-30)

> **A proposal, researched, not built.** No code changes here. Every step that widens what ships,
> or changes a default, needs a dated `decisions.md` entry first (CLAUDE.md, *four questions*).
> Context: `outstanding.md` §1.4 (store routes, the F-Droid correction, Google's developer
> verification).

**Goal.** Someone installs formicaria once from an F-Droid-style client and never thinks about
updates again; the app says plainly where it came from and who updates it; switching install
source, when it is ever needed, is a guided step that cannot lose notes.

**The idea that makes it cheap: one APK, signed with our key, for every channel.** Obtainium, our
own F-Droid repo, IzzyOnDroid and a reproducible f-droid.org build can all deliver the *same* file.
Then no user ever changes signature, and the switch guide (§6) is only for the rare case.

**No lock-in (owner, 2026-10-30).** *"One should still be able to continue downloading and updating
also with our current methods, to not bind us to a particular method; our current one works
nicely."* The website download and the in-app updater stay a first-class channel, not a fallback.
F-Droid-style channels are added beside it, never instead of it. Because every channel ships the
same signed APK, a person can move between channels without reinstalling.

## 2. Phase 0 — fix first, whatever the channel

1. **Check the assistant's first launch.** The phone's `is_enabled` defaults to true when
   `agent.json` is missing (`mobile/src-tauri/src/agent.rs:221-230`), `agent::start` runs at every
   launch (`mobile/src-tauri/src/lib.rs:146-150`), and a first enable fetches the default model
   (`agent.rs:744-757`). So a fresh install **may start the weights download without the consent
   dialog**. Confirm on a device. If true, it is a bug on its own (a large unasked download) and a
   blocker for F-Droid and IzzyOnDroid. Exit test: a fresh install makes no network request until
   the person accepts the dialog (checked with a network capture).
   **Traced in code 2026-10-30 — confirmed, device check still to do.** `agent::start`
   (`mobile/src-tauri/src/agent.rs:724-730`) → `is_enabled` is true with no `agent.json`
   (`:221-230`; its comment says the default exists so *"an app update does not silently turn off
   a working agent"*) → `launch` (`:739-`) finds no model, so `first_enable`, and spawns the
   runner → Myrme v0.12.1 `Tools::run_in_process` (`fm-agent-run/src/host.rs:577-`) calls
   `fetch::ensure_model` and `ensure_mmproj` before starting. For the phone default
   `qwen3.5-0.8b` (Myrme `models.toml:238-249`) that is **507,154,688 + 204,987,232 bytes, about
   712 MB, from Hugging Face**, on any network (no Wi-Fi or metered check found in
   `fm-agent-run`), with no dialog. The Settings dialog that shows sizes and licences is only on
   the enable path, which a fresh install never takes. **Fix direction:** keep the default *on*
   only when a model is already on the phone (the update case the comment protects); with no
   `agent.json` and no model, start *off* and offer the assistant with the existing dialog.
2. **Keep the in-app updater working as today, and make it opt-in in the stores' sense, in the
   same APK.** Today's flow (website install, daily check, press to install) must keep working
   unchanged in practice. Two ways to square that with *"clearly opt-in (i.e. disabled by
   default)"* (IzzyOnDroid; F-Droid's policy asks the same), to be decided:
   - **(a) One question at first launch** of a non-store install: *"Check for new versions on
     GitHub? Downloads come from github.com/formicaria-org/formicaria, signed with our key."*
     One tap keeps today's behaviour; the setting stays in Settings. Off until answered.
   - **(b) Default by installer of record** (`PackageManager.getInstallSourceInfo`): on for a
     browser or package-installer install, off and hidden for a store client. Smoother, but a
     reviewer reading the code may still call it "on by default".
   In both, when a store client is the installer of record, the update rows say *"Updates come
   from <store>"*, and the person can still turn the GitHub check on. **Chosen: (b)**, owner
   2026-10-30 (`decisions.md`, *the Android update check follows who installed the app*); (a)
   stays the answer if a store review objects. A separate store flavour
   (build without `update`) is the last resort if review insists, since it breaks one-APK.
   Exit tests: a website install keeps getting updates after at most one tap; a store install
   makes no update request until the person turns the check on.
3. **Large attachments on the phone.** With no restic on Android, anything above `git_assets_max`
   exists only on the phone. The switch guide (§6) must count them before uninstall. Exit test:
   the count matches `blobs/` minus what git holds.

## 4. Phase 2 — our own F-Droid repo, from our releases

> **Built 2026-10-30, switched on the same day** (repo key fingerprint
> `5D3F5309005F299E32FBA61D27921AA773BD46675A595CD9C6515022D2AE30B6`) (`decisions.md`, *our own F-Droid repo*). As built,
> the steps below differ from the sketch in three ways: the release does not deploy the site itself
> but dispatches `pages.yml` on `main` (Pages deploys from `main`; the release job holds no secret);
> the repo passwords stay in the environment; and the script refuses any APK not signed with our
> pinned certificate. Files: `ci/fdroid-site.sh`, `ci/fdroid-repo.sh`, `fastlane/metadata/android/`,
> the `fdroid` pixi environment, a step in `pages.yml`, job `fdroid-site` in `release.yml`.

The cheapest route to "F-Droid updates it for me", with our signature and no review.

1. **Repo layout.** `fdroid init` makes a repo signing key (a **new** secret, held like the APK
   keystore: off the build runner, backed up off-machine); `fdroid update` writes the signed index
   ([Setup an F-Droid App Repo](https://f-droid.org/docs/Setup_an_F-Droid_App_Repo/): custom repos
   *"can just be 'simple binary repos' of any APKs"*).
2. **Publish with the site.** A release job places the signed APK in `fdroid/repo/`, runs
   `fdroid update`, and `pages.yml` publishes it beside `site/` and `/manual/` (`pages.yml:1-14`).
   Keep the last 3 APKs (about 85 MB).
3. **Metadata in the repo.** Add `fastlane/metadata/android/en-US/` (short and full description,
   icon, screenshots) and `changelogs/<versionCode>.txt` (max 500 characters), written from the
   annotated tag message at release time.
4. **Install page.** The Get-it page shows the repo URL, its fingerprint and a QR code.
5. **Toolchain.** `fdroidserver` enters through pixi (conda-forge or a pinned pip package), so
   the house rule holds; needs a `#toolchain` entry.
6. **Exit test.** On a clean phone: add the repo, install, publish a test release, and see it
   install unattended after the client's first update prompt (F-Droid client ≥1.19, Android 12+).

## 6. Transparency in the app, and the rare switch

> **2026-10-30:** item 1's store line is built (Phase 0.2: *"Updates come from F-Droid…"*). Item 2,
> the switch guide, is **not built**: with one APK for every channel no one has to switch, so it
> waits until a channel ever signs with another key.

1. **Settings → About** shows: installed from (Obtainium / F-Droid / IzzyOnDroid / our repo /
   website, from the installer of record), who updates it, and the signing-certificate digest the
   manual already explains (`docs/src/user/android.md:83-98`).
2. **Switching to a build with another signature** (only if a channel ever signs with its own key):
   - *Before uninstalling*, one screen: all notes synced, or *N changes not synced yet*;
     *N attachments exist only on this phone* (§2.3); uninstalling deletes everything in the app.
   - *After installing*, the first screen offers *restore from your other device* (same remote,
     then sync), and says the assistant's model downloads again.
   Same option names on phone and desktop; nothing drawn over working views.

## 7. Google developer verification

> **Chosen 2026-10-30: do not register now.** It costs identity, not money, and changes nothing for
> people who already have formicaria. Revisit before Google's announced 2027 global rollout, when
> the choice between the free limited account and a full one can be made with the real rules.

From 2026-09-30 certified devices in a first set of countries need apps from verified developers;
global in 2027 (`outstanding.md` §1.4). Choices, for a decision entry: register the signing key
with Google (US$25 once plus ID; then every channel installs without friction), a free
limited-distribution account (reported: up to 20 explicitly authorised devices, no fee, no ID), or
no registration (users take the one-time "advanced" flow or ADB). None blocks Phases 1–4.

## 10. Switching Phase 2 on (the owner, once)

Run on the laptop, in the repository. Each command is complete; `keytool` asks for a password
twice — use one you can store in a password manager.

1. Create the repo key (separate from the APK key; keep both backed up off-machine):

   ```sh
   mkdir -p ~/.config/formicaria && pixi run -e fdroid keytool -genkeypair -keystore ~/.config/formicaria/fdroid-repo.p12 -storetype PKCS12 -alias formicaria-fdroid -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=formicaria F-Droid repository"
   ```

2. Add the four secrets to the GitHub repository (the two password prompts take the password from
   step 1):

   ```sh
   base64 -w0 ~/.config/formicaria/fdroid-repo.p12 | gh secret set FDROID_KEYSTORE_B64 --repo formicaria-org/formicaria
   ```
   ```sh
   gh secret set FDROID_KEY_ALIAS --repo formicaria-org/formicaria --body formicaria-fdroid
   ```
   ```sh
   gh secret set FDROID_KEYSTORE_PASS --repo formicaria-org/formicaria
   ```
   ```sh
   gh secret set FDROID_KEY_PASS --repo formicaria-org/formicaria
   ```

3. Publish once by hand (later releases do it themselves):

   ```sh
   gh workflow run pages.yml --repo formicaria-org/formicaria --ref main
   ```

4. Check it: open https://formicaria-org.github.io/formicaria/fdroid/ on the phone, add the
   repository in F-Droid, and confirm F-Droid offers the installed version as up to date.
5. Then add one line to `site/get.html` and `docs/src/user/android.md` pointing at
   `https://formicaria-org.github.io/formicaria/fdroid/` — not before, because the site's link
   check fails on a page that does not exist yet.

**Rehearse without publishing** (a throwaway key, nothing leaves the laptop): see the commands at
the top of `ci/fdroid-repo.sh`; `sh ci/fdroid-site.sh <dir>` with `FDROID_KEYSTORE_B64` set builds
the real repo into `<dir>`.
