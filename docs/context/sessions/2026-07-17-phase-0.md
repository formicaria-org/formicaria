# 2026-07-17 — Track C Phase 0: the collaboration gate is open

**Outcome:** all four Phase 0 items in [`plan.md`](../plan.md) are implemented, regression
-tested, and driven end-to-end against a real `fm-serve`. `pixi run ci` green (134 UI
tests, full Rust workspace, deny, checks, docs). Phase 0 is folded out of `plan.md` to a
one-line pointer; **Phase 1 is the next work.**

This is the session that made a second person survivable. Nothing here is a feature; every
item was a live single-user bug that becomes data loss the moment a vault is shared.

## What landed

- **Tolerant loader** — `reindex` skips an unreadable note instead of propagating, so one
  conflicted `.md` no longer fails `FileStore::open`. A vault that won't open is one whose
  conflict UI can never render to fix it, and a frontmatter conflict is the *guaranteed*
  shape of a concurrent edit (`updated:` is rewritten on every save). Skipped notes land in
  `ReindexStats.skipped` **and** `FileStore::skipped()`.
- **Skip-and-*report*** — `fm-serve` names the unreadable notes on stderr at startup. The
  skip alone traded a loud crash for a **silently missing note**, which is the worse
  failure; the terminal now says which file and why. The in-app list stays Phase 1.
- **Auto-commit refuses mid-merge** — `commit_all` returns `Ok(false)` when any path is
  unmerged. `add -A` would otherwise stage the conflict markers (git reads that as "the
  human resolved it") and commit `<<<<<<<` as the note's content, 5 s after the pull.
- **`push_squashed` ancestry guard** — squash only when the tracking ref is an ancestor of
  `HEAD`. Design-doc §19's trap: `reset --soft` onto a *fetched* ref puts their tip under
  our tree and pushes as a clean fast-forward that nothing rejects. A count of unpushed
  commits reads as "normal" in exactly that case — ancestry is the question, "how many"
  never was. **This one had to land before anything can fetch**, i.e. before Phase 1.
- **A real git identity** — the last item, and the only one started this session. See
  `decisions.md`; the short version is that the placeholder now survives *only* for a vault
  with no audience, `identity()` reports it as nobody, and `set_remote` refuses while it
  stands. Landed with its UI: the backup panel asks for a name and email, but only when
  `backup_status.identity` is null.

## Decisions made

- **Don't just delete the `formicarium@localhost` fake** (which is what `plan.md` asked
  for, literally read). Git can't invent an identity on a non-FQDN host, so deleting the
  fallback means a fresh vault cannot commit — and the auto-commit swallows errors, so the
  notes would stop being versioned *silently*. Phase 0's premise is "each item is a live
  single-user bug"; a fix that introduces one fails its own test. The placeholder is now
  scoped to what it's honest for and detected by value. Full entry in `decisions.md`.
- **Enforce at `set_remote`, not `commit_all`.** A refusing auto-commit is a silent stop,
  which is worse than a fake name on a private commit.

## Verified

Beyond `pixi run ci`: a real `fm-serve` over a temp vault holding one conflicted note and
one good one. Startup warned and named `conflicted.md`; `search` still returned the good
note; `set_git_remote` was refused with our message and `backup_status.identity` was
`null`; with a name+email it returned 200, and `git config` then showed the vault really
commits as `Ravi Patel <ravi@example.org>`.

## Traps found on the way

- **The git tests were not hermetic, despite the file header saying so.** `ensure_identity`
  only writes the placeholder when `user.email` is unset — but every developer has a
  `~/.gitconfig`, so on this machine it wrote nothing and the first identity tests passed
  the *developer's own* address around. Fixed with a `no_identity()` helper that sets the
  placeholder **repo-locally** (local beats global), so the test states the world it means.
  Worth remembering: any future test that asserts on git config must pin it locally.
- **`formicarium@localhost` is now load-bearing.** It is a sentinel `identity()` matches by
  value. The Phase 2 rename must not touch it — noted in `plan.md`'s rename section.

## Left not-working

- **Panel errors read `io error: …`** — `StoreError::Io`'s Display prefix reaches the user
  verbatim ("io error: tell us who you are first"). Pre-existing and affects every backup
  message, not just the new ones; wants a `StoreError::Refused(String)` variant with no
  prefix. Not done: it's a cross-cutting change to the error taxonomy that no plan entry
  rules on.
- **An unreadable note is still invisible in the browser** — stderr only. Phase 1's
  conflict surfacing owns the in-app list; the `known-issues.md` entry was rewritten from
  "bricks startup" to reflect the new, smaller gap.
- Everything Phase 1 onward: the `FileStore::put` staleness guard (*the* lost-update bug),
  incremental reindex, the polls, `pull`, and the `.md` merge driver.
