# 2026-07-17 — Track C Phase 2: the core, and the decision it exposed

**Outcome:** Phase 2's seam-level half is built and tested — `Object.vault`, the
`candidates` federation seam, and `MultiStore`. `pixi run ci` green. **The product half is
deliberately not built**: wiring `MultiStore` into `fm-serve` turns out to depend on two
decisions [`plan.md`](../plan.md) never made, and both are the kind that are cheap to make
on purpose and expensive to discover later. Stopped and wrote them down instead.

Third session of the day, after `2026-07-17-phase-0.md` and `-phase-1.md`.

## What landed

- **`Object.vault`** — a real field with an explicit `get()` arm above the `extra`
  fallback, so `Predicate::Prop` answers "filter by vault" with no query-engine change.
  Derived by the store that loads it (`FileStore::named` + `hydrate`), **never**
  serialized.
- **The `candidates(&Filter) → (Vec<Object>, residual Filter)` seam** — `Store::query` is
  now a default method: narrow per store, rank once over the union. Replaces `query` as
  the thing a backend implements.
- **`MultiStore`** — reads concatenate, writes route by `obj.vault` to exactly one child,
  `get` takes the first hit (ULIDs are globally unique, so there can only be one).
- **`ObjectMeta.vault`** so a card can be badged with its audience.

## What the tests earned

- **The byte round-trip test caught the trap on its first run.** The plan says to write it
  *first* and it was right: `to_file` writes every `extra` key back, so a `vault` key in
  `extra` really did serialize into frontmatter — a permission-shaped string sitting in
  content, which is precisely the forgeable label decision 4 refuses. `to_file` now skips
  it explicitly, and `from_file` strips it, so a hand-typed `vault: everyone` cannot
  survive a rewrite or talk its way into another audience.
- **FTS really does federate.** The test searches `reunion` and expects 10 hits for notes
  containing `réunion`, across two vaults. Only FTS5 (`remove_diacritics 2`) folds that;
  the pure engine's substring scan does not. So the assertion proves the index answered in
  both children *and* that the residual filter stopped the engine re-running `Text` and
  throwing the folded matches away. That is the whole argument for `candidates` over
  `load_all`, in one number.
- **A `MultiStore` over one vault answers identically to that vault.** If the plural
  changed the singular's answers, the abstraction was not free.

## The decision Phase 2 actually blocks on (this is the finding)

`MultiStore` slots behind the `Store` trait, so reading across vaults is done and the UI
could badge cards tomorrow. But **all 16 of `fm-serve`'s `state.vault` uses are
per-vault**, and they are two distinct problems the plan collapsed into "wiring":

1. **Git is per-vault by definition.** One vault = one repo = one remote = one collaborator
   list, so `commit`/`push`/`pull`/`set_git_remote`/`set_identity`/`backup_status` each need
   a vault argument — and the backup panel stops being a panel and becomes a per-vault
   list: *N* remotes, *N* identities, *N* unpushed counts, *N* "someone pushed". That is
   the panel's whole shape, not a parameter. The tempting shortcut — let `push` mean "the
   first vault" — is exactly the overstatement `destination.ts` was written to prevent: a
   backup that silently skips the lab vault.
2. **Blobs are per-vault too, and nothing says which vault holds one.**
   `resolve_asset`/`asset_status`/`ingest`/`blob_path` all take a vault path, and a
   `sha256:` reference in a note carries no vault. Either resolution searches every vault —
   cheap, and *correct*, because content-addressing means identical bytes whichever vault
   answers — or references become vault-scoped, which re-couples a note to a location and
   would break the cross-vault links ULIDs give for free. **Searching is almost certainly
   right.** It should still be decided rather than defaulted into.

Neither is hard. Both change what the UI *is*, so the UI cannot be designed first. Written
into `plan.md` under Phase 2 rather than answered here at the end of a long session.

## Left not-working

- **Phase 2's product half**: the vault-list config file (the first app-level config —
  `FM_VAULT` is a single path and a list cannot live inside any one vault), badges, the
  vault filter. `MultiStore` is currently used by nothing but its tests, so by this plan's
  own rule — *a phase that ships only Rust shipped nothing* — **Phase 2 has not shipped.**
- **The rename is untouched**, correctly: it lands when the plural is *true*, and it isn't
  yet. When it does, `formicarium@localhost` in `git.rs` is **not** a rename target — it is
  a sentinel `identity()` matches by value, and renaming it would silently hand every vault
  running on the placeholder a "real" identity, reopening the provenance hole Phase 0
  closed. Flagged in `plan.md`'s rename section too.
- Everything carried from Phases 0–1: the automatic 15–30 s remote poll, conflict
  surfacing outside the backup panel, `skipped()` being stderr-only, `io error:` prefixes.
