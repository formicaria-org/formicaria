# 2026-07-17 — Track C Phase 2: the plural is true

**Outcome:** multi-vault ships. A set of vaults, each its own repo and its own audience,
under one set of views. `pixi run ci` green. Verified against two real vaults through the
API, not just in tests. **The rename's trigger is finally met** and is the only Phase 2
item left — deliberately held back as its own commit.

Fourth session of the day, after `2026-07-17-phase-0.md` and `-phase-1.md`.

## What landed

- **`Object.vault`** — a real field with an explicit `get()` arm above the `extra`
  fallback, derived by the store that loads it, **never serialized**. `Predicate::Prop`
  answers "filter by vault" with no query-engine change, exactly as decision 5 predicted.
- **The `candidates(&Filter) → (Vec<Object>, residual Filter)` seam** — `Store::query` is
  now a default method: narrow per store, rank once over the union. This is what a backend
  implements now.
- **`MultiStore`** — reads concatenate, writes route by `obj.vault` to exactly one child,
  `get` takes the first hit (ULIDs are globally unique, so there can only be one).
- **The vault-list config file** — `~/.config/formicarium/vaults.json` (or `FM_VAULTS`).
  The first app-level config file, and a deliberate break with "no new config file": a
  *set* of vaults cannot live inside any one vault, and `FM_VAULT` is a single path.
  Absent = the single vault, so nothing to migrate and a list of one behaves exactly as
  before.
- **Per-vault git**, **searched blobs**, **badges**, and a **vault filter**. See
  `decisions.md` for the three rulings behind those.

## Verified against two real vaults

Not tests — the actual server, two vaults, a bare remote:

- A capture naming no vault landed in the default (`personal`).
- A note dropped into the lab vault by hand appeared on the board next to a personal one,
  **each badged with where it actually lives**.
- `vault:` appeared in **zero** files (`grep -c` across both vaults: 0, 0).
- `backup_status` came back a per-vault list.
- A remote set on `lab` left `personal` untouched, and `set_git_remote` with a **typo'd
  vault name was refused**, not defaulted.
- Pushing `lab` sent lab's notes to lab's remote; `personal`, with no remote, stayed put.

## What the tests earned

- **The byte round-trip test caught the trap on its first run.** The plan says write it
  *first* and it was right: `to_file` writes every `extra` key back, so a `vault` key in
  `extra` really did serialize into frontmatter — a permission-shaped string sitting in
  content, which is exactly the forgeable label decision 4 refuses. Both `to_file` and
  `from_file` now refuse it, so a hand-typed `vault: everyone` cannot survive a rewrite or
  talk its way into another audience.
- **FTS really does federate.** Searching `reunion` must return 10 notes containing
  `réunion` across two vaults. Only FTS5 (`remove_diacritics 2`) folds that; the pure
  engine's substring scan does not. So the number proves the index answered in *both*
  children **and** that the residual filter stopped the engine re-running `Text` and
  discarding the folded matches. That is the whole `candidates`-over-`load_all` argument
  in one assertion.
- **A `MultiStore` over one vault answers identically to that vault.** If the plural
  changed the singular's answers, the abstraction was not free.

## The decisions this phase forced (full entries in `decisions.md`)

The plan called the fm-serve work "wiring". It wasn't: all 16 `state.vault` uses are
per-vault, and they were two different problems wearing one name.

1. **Git is per-vault, so the panel is a list, not a form.** N remotes, N identities, N
   "someone pushed" — there is no honest way to collapse them. The shortcut (let `push`
   mean "the first vault") is the overstatement `destination.ts` exists to prevent, so the
   verdict now names the vaults that did *not* make it.
2. **Blob resolution searches every vault** — correct, not merely convenient, because
   content-addressing means whichever vault answers has the same bytes. Vault-scoping
   references would re-couple notes to locations and break the cross-vault links ULIDs
   give for free.
3. **restic still doesn't respect vault boundaries** — one repo, one password, every
   vault. Stated in the panel rather than implied away, because backup is not sharing.

## Left not-working

- **The rename.** Its trigger is met — the plural is literally true — and it is held back
  on purpose: a rename should be its own commit so it reads as "only strings moved" rather
  than hiding inside a feature diff. **Re-read `plan.md`'s "The name" first.**
  `formicarium@localhost` is a sentinel `git::identity()` matches **by value**; renaming it
  hands every vault still on the placeholder a "real" identity and silently reopens the
  provenance hole Phase 0 closed. The Excalidraw `source` literal is written into every
  board's JSON on disk and is not a rename target either.
- **The vault filter is client-side.** Right as a *view preference* — it lives beside the
  column order in localStorage — and every card is already on the client, but it means
  hiding a vault does not spare the query. Fine at this scale; revisit with the perf budget.
- **`ingest`'s vault comes from a query param nothing sends yet.** It defaults to the
  default vault, so a PDF dropped onto a lab note currently lands in `personal`. The
  backend takes the argument; the UI does not pass it. Small, and wrong in a quiet way.
- Everything carried from Phases 0–1: the automatic 15–30 s remote poll, conflict
  surfacing outside the backup panel, `skipped()` being stderr-only, `io error:` prefixes.
